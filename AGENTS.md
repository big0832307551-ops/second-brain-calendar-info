## ONE PROMPT → DONE v2.0 — рабочий гейт (22.11.2026)

Канонический общий регламент — `/Рабочие правила и скилы/Igor_Working_Rules.md` в ChatGPT Library. Он может быть недоступен из Codex, поэтому **самостоятельно применяй эту краткую выдержку**; оставшиеся выше проектные ограничения имеют силу. Цель: один запрос → проверенный результат в одной доступной сессии, не план вместо результата.

1. **Приёмка:** определить цель, результат, формат/место и критерии готовности. Не спрашивать уже известное.
2. **Проверка фактов:** изучить только релевантные исходники, решения, `main`, PR, CI, логи и развёрнутую версию. Для каждого критерия: `выполнено / не подтверждено / блокер`.
3. **Разница и NO-OP:** работать только с незакрытыми критериями. Если всё доказано — не создавать ветку, PR, код или новый тест. Отсутствие доказательства не равно отсутствию реализации.
4. **Выбор среды:** сообщать экономный вариант `Чат`, `Codex/Work` или `Чат → Codex/Work`. При передаче сохранять уже проверенное и не начинать диагностику заново.
5. **Самостоятельность:** выполнять все разрешённые шаги до проверенного результата; не останавливаться на плане/PR. Блокер — выполнить независимую часть и точно объяснить причину. Не обещать фоновую работу без действующего запуска.
6. **Причина → правка → тест:** до исправления выяснить факты и гипотезу; менять только нужное. Сначала адресный тест; одинаковые прогоны без нового кода/фактов запрещены. Перед выпуском выполнять все необходимые CI, проверки безопасности, данных и приёмки.
7. **Ресурсы и качество:** минимально достаточная модель, контекст и инструменты; без дублирующих агентов и отчётов. Проверить реальный результат и доступность, отличать фикстуры от живой интеграции; не выдумывать данные расхода токенов.
8. **Сохранность:** оригиналы, секреты, пользовательские данные и конфигурацию не затрагивать сверх задачи; платные/необратимые/существенные действия согласовывать. Убирать лишь свои временные артефакты, закрывать только свои окна.
9. **Фиксация и отчёт:** использовать существующий журнал проекта без дублей. Формат: `сделано / доказательство / не сделано и почему / следующий шаг`. «Готово» — лишь по всем критериям.
10. **Новые правила:** явное утверждение владельцем постоянного правила — разрешение внести его в основной регламент и **только применимые** `AGENTS.md` без повторного вопроса. Сначала сверить, потом точечно записать и перепроверить; запреты на платные/опасные операции остаются.

`AGENTS.md` — инструкции, не технический блокировщик запусков или измеритель токенов. Не создавать повторную проверку только чтобы показать соблюдение этих правил.

## GitHub и Markdown — обязательный контроль сохранности (22.11.2026)

1. Каждый программный проект вести в GitHub под основным владельцем `big0832307551-ops`. Сначала искать существующий репозиторий, не создавать дубликат. Для **новых** репозиториев приватность обязательна; **существующие** настройки видимости не менять без согласования.
2. Поддерживать вместе с исходниками документацию **именно Markdown (`.md`)**: `README.md` (назначение/запуск/восстановление), `AGENTS.md` (правила), `ROADMAP.md` (план), `TASKS.md` (задачи), `CHANGELOG.md` (история), `docs/*.md` (инструкции и архитектура).
3. До создания недостающего файла проверять аналоги и ссылки: сохранять полезные материалы, не плодить дубликаты и пустые заглушки. Обновлять только сведения, которые затронуты работой.
4. После существенных изменений сделать `git commit` и `git push`; независимо проверить в **удалённом GitHub** актуальный SHA, нужные исходники и Markdown-файлы. Локальный коммит без проверенного push **не означает сохранение работы**.
5. Проверять работоспособность и доступность результата отдельно от коммита/CI; фиксировать возможность отката/восстановления. Рабочие данные, секреты, токены и конфигурацию вне Git сохранять отдельно безопасным способом, не публиковать в репозитории.
6. Перед отчётом «Готово» провести полный гейт: цель и критерии → сверка выполненного/NO-OP → адресная работа → диагностика/тесты → GitHub push и удалённое чтение → документация Markdown → восстановимость/уборка → короткий отчёт. Если пункт нельзя подтвердить, указать блокер.
7. Полноту постоянных инструкций сверять на трёх уровнях: **ChatGPT**, **Codex**, **AGENTS.md** (глобальный и проектный); не путать сохранение в Library с автоматической загрузкой в Codex. Не утверждать факт чтения локального файла или настроек без доступа к ним.
